# V7.2.2 implementation plan (before implementation)

Baseline: immutable 71-file V7.2.1 final source. All 538 existing tests passed before implementation. Live JP calculator and local calculator match byte for byte. Exact rules are in CURRENT_PRICE_RULES.md; official API contracts in PAYPAL_OFFICIAL_API_RESEARCH.md.

1. Preserve all existing calculator, CSS, audio, forms, review and Kakao source bytes. Only index.html receives links to two new isolated checkout assets; markup is created by the checkout script. Add four shared server modules and three thin endpoints without adding dependencies. PAYPAL_SETUP.md will point to the current setup while preserving its historical V7.2 record.
2. Mirror actual jp.js rules in a pure server pricing module and compare across all branches against the actual unchanged frontend calculator. No fixed amount or amount allowlist. Validate safe integers and PayPal's documented numeric ceiling; consult is not payable.
3. Use official v6 clientId / paypal-payments / eligibility / paypal-button / one-time session, Orders v2, native fetch, JPY integer strings, digital goods, NO_SHIPPING in experience_context. Sandbox UI requires localhost, a trusted JP preview, or explicit paypal_test=1 on Production. Unknown environment fails closed. No deployment or Live calls.
4. Config sets an HttpOnly same-site session and returns a purpose-bound CSRF token (not a PayPal token) with public config. Exact same-origin POST and CSRF checks precede JSON parsing and external calls. Separate lian-paypal-orders-v1 store with strong reads and checked conditional writes.
5. Create accepts checkoutKey UUID and quote {plan,partyType,participantCount,extraVocalTracks,options,rush}. Options are harmony, adlib (existing combined double/adlib checkbox), private. Solo count=1, duet=2, group>=3. Persist canonical quote, fingerprint, server amount, session binding, environment and separate request UUIDs before external calls. Stable IDs, leases and CAS prevent concurrent duplicate operations.
6. Capture accepts checkoutKey and orderId. Require own local record and session, validate server GET merchant/reference/currency/amount/approval, verify actual COMPLETED capture gross amount, then persist before reporting success. Completed requests are idempotent. Unknown outcomes remain recoverable on the same order; no automatic new payment.
7. Checkout UI uses the existing estimate for display comparison only; sends selections only. Lock price controls while pending, preserve native form independently, show server-verified success, allow explicit new quote after completion. One new responsive node under desktop estimate/mobile mini estimate; no duplicate SDK. Cancellation is not success.
8. Add offline API mocks with realistic Blobs modified:false/ETag CAS and PayPal errors, concurrency/recovery/security tests plus real-browser mocked v6 flow, 320px mobile and ordinary Production gating. Re-run all 538 existing tests with documented adaptations for authorized new checkout bootstrap only. Bundle all functions and syntax-check source.
9. Package site and detailed verification artifacts without .env, credentials, dependencies or build caches. Clearly distinguish mocks from real Sandbox verification; no claim of live account configuration, real message send or deployment.

Frontend contract: create -> {id,amountJPY,currency:'JPY'}; capture -> {status:'COMPLETED',id,amountJPY,currency:'JPY'}. API failures -> {error:{code,message,recoverable}}. Codes PROCESSING/PAYMENT_UNCERTAIN/PAYMENT_PENDING require same-order status recovery; ORDER_NOT_APPROVED/INSTRUMENT_DECLINED allow explicit approval retry. Endpoints carry paypal_test=1 when page has it. POST header X-Lian-PayPal-CSRF uses config csrfToken. All fetches same-origin credentials. Config disabled -> {enabled:false,environment:'sandbox',currency:'JPY'}.
